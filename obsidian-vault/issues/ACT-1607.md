# ACT-1607: Sail can't model implemented/unimplemented CSRs, which causes SsstricSm signature mismatch on cores that have certain extensions dependent CSRs but not all of them

Ssstrict sweeps unimplemented CSRs and opcodes; a core that implements only some counter CSRs of Zicntr/Zihpm cannot be described to Sail, so the trap count differs.

## What fails

SsstrictSm-* fail 'Mismatch in trap signature pointer offset' (a different number of illegal-instruction traps than Sail).

## What the maintainers concluded

Maintainers: a core that does not trap on everything Ssstrict expects does not implement Ssstrict; remove Ssstrict from the UDB config and the tests are skipped. Read-only-zero counters are fine if declared implemented.

## How triage treats a match

Check which swept CSR the board implements differently (see also ACT-1899, ACT-1900, ACT-1924 for priv-1.11 CSRs) before calling it hardware.
