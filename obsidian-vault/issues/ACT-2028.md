# ACT-2028: sv39_exceptions_Zaamo test6 fails on my platform (implementation-defined exception order)

sv39_exceptions_Zaamo/Zalrsc test 6 (invalid PTE + misaligned VA, M-mode with MPRV) expects one exception, but the priority between translation and misalignment is implementation-defined.

## What fails

The DUT reports a page fault where Sail expects address-misaligned (or the reverse) for a misaligned AMO/LR/SC through an invalid PTE.

## What the maintainers concluded

Tracked in sail-riscv#1793; sail-riscv 0.14 can express both orders (memory.misaligned.exceptions, and for LR/SC the equivalent option, ACT #2267; ACT-2112 is the same report for LRSC).

## How triage treats a match

Set the board's sail.json misaligned-exception options to its real priority before suspecting hardware; a cause mismatch only in these subtests is a configuration issue.
