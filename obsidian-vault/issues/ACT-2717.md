# ACT-2717: [Bug] Hypervisor tests on real hardware: Milk-V Megrez (SiFive P550, H draft 0.6, priv 1.11): 123 built, 84 ran, 54 pass

Our report of the H tests on the Megrez. The maintainer traced the 39 SvH/SvHSm self-check failures to the board config: the UDB yaml declares S/Sm 1.12 (needed to generate H tests), so SvH writes menvcfg.ADUE/PBMTE through T-SBI; the P550 (and Sail with Privileged_ISA_1_11) has no menvcfg, the write traps inside T-SBI dispatch and the test loops until the trap signature overflows.

## What fails

Before 2026-10-12: SvH_*/SvHSm_* (sv39x4/sv48x4 and VS-stage translation) failed their Sail
self-check with 'Trap signature overflow ... Increase TRAP_SIGUPD_COUNT' and never ran on the
board. Since the config fix (ACT `megrez-hypervisor` ef0dee9d2, sail.json `Privileged_ISA_1_12`)
they build and pass on Sail, run on the board, and fail there with an illegal-instruction trap
on `csrrc menvcfg` (CSR 0x30a) inside T-SBI, because the P550 has no menvcfg.

## What the maintainers concluded

davidharrishmc (2026-10-06): the overflows come from the Megrez config (UDB S/Sm 1.12 but sail.json
priv 1.11); with Privileged_ISA_1_12 all 39 pass on Sail; raising TRAP_SIGUPD_COUNT would not help.
These tests write menvcfg and cannot run on a priv-1.11 hart as written. ACT may make a trapping
T-SBI instruction fail with a clear message instead of looping. Reproduced locally: SvH/SvHSm 41/41
and all 121 H-suite tests pass the Sail self-check with Privileged_ISA_1_12.

## How triage treats a match

Context only (not auto): the SvH/SvHSm failures that are this issue trap on `menvcfg` (0x30A) or
`henvcfg` (0x60A), and the board rule for absent CSRs already classifies those precisely as a
known deviation. Megrez weekly #8 (2026-10-12, ACT `megrez-hypervisor-sail015`, Sail 0.15) showed
other SvH failures with the same test names that are not this issue: `hlvx.wu` load page faults
where Sail reads the value (SvH_sv39x4_hlv, SvH_sv48x4_hlv), guest page faults with different
values (e.g. SvHSm_sv39x4_guest_faults_vs) and SvH_sv39x4_gpa_wide. Matching every SvH test by
name hid them as known deviations; they need their own analysis.
