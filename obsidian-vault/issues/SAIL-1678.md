# SAIL-1678: LR/SC reservation not invalidated by same-hart store in Sail (Zalrsc)

Sail kept an LR reservation across a store from the same hart; real cores may drop it (cache-line reservation tracking), so SC returns 1 where Sail expects 0.

## What fails

An SC after a same-hart store into the reservation set fails on hardware (xSC=1) while the Sail signature expects success (xSC=0).

## What the maintainers concluded

Both outcomes are legal: the spec does not say what a same-hart store does to the reservation. Sail added a config option to invalidate the reservation on same-hart stores; ACT dropped the over-constrained test (ACT-1381).

## How triage treats a match

With Sail >= the release containing PR #1684 and the option set for the board, this should not recur. If it does, the board's sail.json lacks the option.
