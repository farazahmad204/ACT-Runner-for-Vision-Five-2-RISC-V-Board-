# ACT config generation assets

`scripts/gen_act_config.py <spec> --out-dir <dir> [--act-root <ACT checkout>]`
turns a short board spec into an ACT 4.1 DUT config folder: the UDB config,
`sail.json`, `link.ld`, `rvmodel_macros.h`, both `test_config` files,
`suites.yaml`, `generation_report.yaml` and `README.md`. The generator makes
no network or model calls.

| File | Role |
|---|---|
| `../board_specs/<board>.yaml` | Board spec shared with `gen_board_files.py`: ISA string, priv version, test hart, payload window, CLINT/PLIC/UART, CSR facts and evidence. See `../board_specs/README.md`. |
| `udb_library.yaml` | Generated by `scripts/build_act_library.py`. Holds the UDB extension versions and each parameter's `definedBy`, with defaults taken from the reviewed board configs. |
| `sail_base.json` | Sail 0.14.1 stock rv64 config plus the harness settings that VF2 and Megrez share. All extensions are off. |
| `rvmodel_macros.h.in`, `link.ld.in` | Templates taken from the reviewed Megrez config. |

## How each value is chosen

1. **Computed from the spec:** extensions, PMP, HPM counters, IDs, alignments, PLIC/CLINT addresses.
2. **Spec overrides:** the `params:` and `sail:` sections.
3. **Defaults:** a library default from a reviewed board, listed as UNVERIFIED in the generated `README.md`.
4. **Missing:** the run exits with code 2.

Parameters are kept only when their UDB `definedBy` condition holds, including
extension versions. For example, `CONFIG_PTR_ADDRESS` needs Sm >= 1.12.

## Hypervisor

H at 1.0 is tested. For a draft H, set `hypervisor.hardware_version`. By
default H is then excluded from UDB but kept in Sail. With
`hypervisor.test_as_ratified: true`, the generator instead declares H 1.0 and
S/Sm 1.12 for UDB, and records both as deviations.

## Regression evidence (2026-10-03)

The Megrez spec reproduces the hand-made config:
- same UDB extensions and versions, and UDB `validate cfg` passes;
- `sail.json` identical;
- **132/132 ELFs with identical loadable contents** (InterruptsSm, Sstvecd,
  Zba, PMPSm; hardware and signature builds).

The VF2 spec also passes UDB and Sail validation.

The generator differs from the hand-made configs in places where those
configs contradict themselves:
- UDB `VENDOR_ID_*`/`IMP_ID_VALUE` disagree with `sail.json`;
- VF2 UDB `ASID_WIDTH` 0 vs Sail `asidlen` 16;
- VF2 `sail.json` enables H, Sh*, Ssnpm and Svukte, which the U74 lacks.

## Rebuilding the library

Rebuild it after ACT changes its UDB pin (`framework/src/act/data/Gemfile`):

```bash
python3 scripts/build_act_library.py --udb-spec ~/.local/share/udb/<ver>/gen/resolved_spec/_ --udb-version <ver> \
  --config <megrez udb yaml> --config <megrez hypervisor udb yaml> --config <vf2 udb yaml> --config <bpif3 udb yaml>
```
